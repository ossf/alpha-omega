# **eBPF Foundation Alpha-Omega Engagement**

## **Project Update — September 2026**

This update covers engineering progress and community engagement for the eBPF Foundation's OpenSSF Alpha-Omega project through September 2026\. Work during this period focused on finalizing Kernel Address Sanitizer (KASAN) support for JITed eBPF programs, incorporating community feedback, addressing architecture-specific edge cases, and merging the feature into upstream Linux.

### **Major Developments**

#### **Upstream Acceptance and Merging of KASAN for eBPF**

The primary engineering milestone for this period was the official upstream merging of the KASAN support series for eBPF programs on x86\_64. Following extensive community review and multiple iterations, version 9 of the patch series was merged into the bpf-next tree.

Key highlights of the merged implementation include:

* **Verifier Integration**: Leverages verifier instruction tracking (insn\_aux\_data) to accurately differentiate between stack memory accesses and non-stack memory accesses.  
* **JIT Instrumentation**: Automatically inserts KASAN check calls (\_\_asan\_loadX and \_\_asan\_storeX) into JIT-compiled code for non-stack memory operations, including atomic operations, load-acquire, and store-release instructions.  
* **Precision and Relocation**: Successfully handles verifier instruction patching (such as constant blinding and zero-extensions) by adjusting auxiliary data markings to prevent false-positive instrumentation on stack accesses.

#### **Upstream CI Integration and Allowlist Configuration**

To ensure long-term stability and regression testing across the ecosystem, the KASAN eBPF test suite was integrated into the upstream Linux BPF Continuous Integration (CI) pipeline.

* A pull request was merged into the vmtest infrastructure to configure a SPLAT\_ALLOWLIST, allowing expected KASAN splats generated by the self-tests to pass CI validation without triggering false build failures.  
* The self-tests programmatically validate that out-of-bounds (OoB) accesses and use-after-free (UAF) scenarios correctly emit KASAN reports in kernel logs.

#### **Comprehensive Instruction and Feature Coverage**

During the final review cycles, coverage was expanded to address complex JIT instruction paths and ISA versions:

* **Atomic Operations and Barrier Instructions**: Fully instrumented BPF\_STX | BPF\_ATOMIC operations (including BPF\_FETCH, BPF\_ADD, BPF\_AND, BPF\_OR, BPF\_XOR), as well as LOAD\_ACQUIRE and STORE\_RELEASE semantics.  
* **Immediate Stores (BPF\_ST)**: Added instrumentation for immediate store operations while ensuring Spectre mitigation instructions (BPF\_NOSPEC) remain uninstrumented.  
* **Multi-CPU ISA Version Handling**: Updated test suites using \_\_BPF\_FEATURE\_ST to conditionally test BPF\_ST and BPF\_STX variants across CPU ISA versions (v2, v3, and v4).

### **Additional Engineering Progress**

* **eBPF Selftests Conversion**: Maintained ongoing contributions toward converting legacy shell scripts into the structured test\_progs C framework, improving test execution speed and reliability across multi-architecture CI environments.  
* **Flaky Test Remediation**: Addressed non-deterministic connection failures in network selftests (tc\_tunnel and tc\_edt) by refining socket connection polling and timeout handling.  
* **Community Disclosures and Cleanup**: Upstream patches were accepted to remove deprecated tools (such as xdping) and obsolete shell wrappers from the kernel tree, streamlining the kernel selftest footprint.

### **Current Focus**

* **CI Monitoring**: Monitoring upstream CI builds to ensure ongoing stability of KASAN instrumentation across varied kernel configurations.  
* **Expanded Memory Region Support**: Evaluating requirements and scope for expanding dynamic shadow memory monitoring to additional memory types or architectures.  
* **Selftest Maintenance**: Finalizing remaining test conversions and addressing intermittent CI environment issues.

### **Acknowledgements**

The eBPF Foundation thanks Alpha-Omega for its continued support of this work. The engagement is helping advance practical security improvements for the Linux kernel and the broader eBPF ecosystem through both upstream engineering and community collaboration.
