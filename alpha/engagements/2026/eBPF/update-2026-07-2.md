# **eBPF Foundation Alpha-Omega Engagement**

## **Project Update: July 2026**

This update details progress made during July 2026 on the eBPF Foundation's Alpha-Omega engagement. Engineering work during this period focused on advancing Kernel Address Sanitizer (KASAN) support for Just-In-Time (JIT) compiled eBPF programs in the Linux kernel on the x86\_64 architecture, addressing upstream community review feedback, refining verifier instruction tracking logic, and expanding automated selftest coverage.

## **RFC Review and Community Engagement**

Throughout July 2026, work focused on iterating and refining the upstream eBPF KASAN patch series submitted to the `bpf` Linux kernel mailing list:

* Revisions v3, v4, and v5 of the patch series were published during the month (`20260701-kasan-v3-0-bd09bb942d86`, `20260708-kasan-v4-0-d5c177ab8227`, and `20260709-kasan-v5-0-1c64af8e4e1e`).  
    
* Feedback from community maintainers and automated review tools (Sashiko) led to several design adjustments:  
    
* Kconfig gating logic was updated based on feedback from Andrey Konovalov.  
    
* The dependency on `VMAP_STACK` was removed after confirming it was not required to prevent KASAN runtime crashes.  
    
* Assembly verification using Clang confirmed that compiler-generated `__asan_load` and `__asan_store` routines do not clobber the `r10` and `r11` registers when called from JITed eBPF code.  
    
* Reviews from Ihor Solodrai guided simplifications to stack-access instruction tracking and improvements to atomic instruction test coverage.  
    
* A presentation abstract was submitted for the upcoming Linux Plumbers Conference (LPC) in Prague (scheduled for October 2026\) to share the architecture and current status of the eBPF KASAN integration.

## **Expanded Instruction Coverage and Verifier Integration**

Significant engineering effort was dedicated to improving how the BPF verifier tracks memory access characteristics across program modification and JIT compilation passes:

* **Instruction Auxiliary Data Alignment:** Refactored `adjust_insn_aux_data` in the BPF verifier to ensure the `non_stack_access` flag correctly follows original instructions during verifier patching passes. By recording the original instruction at patching time in `bpf_patch_insn_data` and matching it in the generated patch sequence, regressions were resolved where constant blinding (`BPF_F_TEST_RND_HI32`) caused stack operations (such as `ldx_patched_on_stack`) to trigger false KASAN reports.  
    
* **Context Conversion Handling:** Evaluated instruction rewrites performed by `ctx_convert_access` (e.g., accesses to `skb->ifindex`). Instruction offsets are intentionally not shifted for context rewrites, ensuring that generated load and store instructions remain instrumented.  
    
* **Atomic Instruction Support:** Extended coverage to 64-bit atomic fetch operations (such as `__sync_fetch_and_or`), ensuring `BPF_FETCH` primitives are correctly recognized and instrumented by the JIT compiler.  
    
* **Adaptive Private Stack Interactions:** Identified an edge case under adaptive private stack execution (`PRIV_STACK_ADAPTIVE`), where register allocation maps registers to `X86_REG_R9`. Inlined verifier helpers (such as `bpf_loop()`) generated register-saving instructions (`BPF_STX_MEM`) that defaulted to `non_stack_access = true`, leading to invalid register arguments being passed to KASAN check routines.

## **Testing and Validation**

Kernel selftests within `test_progs` were expanded to validate both detection accuracy and false-positive suppression:

* **Out-of-Bounds (OoB) Testing:** Re-implemented kernel test kfuncs in `bpf_testmod` to programmatically trigger and validate KASAN out-of-bounds reports, adjusting test structures to correct an issue where out-of-bounds access sizes previously defaulted to 8 bytes.  
    
* **Atomic Operation Tests:** Refactored the eBPF KASAN selftest runner to cover 64-bit `BPF_FETCH` atomic operations.  
    
* **Toolchain Compatibility:** Resolved GCC build failures in the `kasan.c` eBPF selftest file.  
    
* **Regression Testing:** Re-validated stack access detection logic against `ldx_patched_on_stack` tests to verify that stack memory operations do not emit unnecessary KASAN instrumentation.

## **Current Focus**

* Resolving register allocation and flag inheritance issues in `adjust_insn_aux_data` for verifier-inlined helpers (such as `bpf_loop`) running under adaptive private stacks.  
    
* Finalizing refinements to stack-access tracking logic to maintain accurate, non-intrusive memory monitoring.  
    
* Preparing revision v6 of the eBPF KASAN patch series for submission to the upstream `bpf` mailing list.
