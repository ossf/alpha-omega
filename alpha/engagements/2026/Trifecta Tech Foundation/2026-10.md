# Zstandard encoder - Monthly progress report

This month we merged 40 PRs spanning more than 350 commits, working primarily on cleaning up the code base and incrementally making more functionality safe.

This cleanup proces, the 2nd milestone "LLM-assisted code cleanup", is the bulk of the work of the software changes to the encoder codebase. At the time of writing, 325 out of a total of 653 functions of the encoder are safe.

We have been [collecting timings](https://trifectatechfoundation.github.io/libzstd-rs-sys-bench/) for a while now, and have a good grasp of the baseline performance. The performance gap versus a GCC-compiled zstd is a couple of percent. With a clang-compiled zstd we've found the difference to be smaller, so part of the difference is due to LLVM. We'll continue to monitor these numbers as we make more code safe (inevitable adding bounds checks) to ensure performance does not regress.

See the [README](README.md) for the deliverables and approach of the project.
