# Curation Overlays

Dirkjan has started working on a proposal to allow consuming organizations to apply supply chain security policies to their view of the crates.io ecosystem. Additionally, providing organizations might be able to supplement additional crates to consumers that opt in to them. There was a lot of discussion at EuroRust about supply chain security and a substantial contingent of Rust Foundation folks attended a popular talk on supply chain security topics, showing that these issues are top of mind for Rust users.

# Signing and Mirroring

Arlo and Walter led a demo to interested project members of our tufops tool, a utility for managing the git repo containing our TUF metadata, demonstrating its ability to rotate crates.io key, sign rustup releases, sign channel manifests, etc.

Arlo and Walter have also been evaluating the trade-offs for different approaches to mirror discovery, learning from other ecosystems and projects that have also had to solve this problem. We anticipate primarily using DNS TXT records as they are easier to override as well as providing an alternative in Cargo’s config.json.

Arlo has been working on our own version of the rust-tuf library which has the features we need and is more spec-compliant than the upstream version.

# crates.io Quarantine

Jess’ [RFC](https://github.com/rust-lang/rfcs/pull/4016) to introduce an availability field to the Cargo index (with values available, quarantined and withdrawn) has continued to progress. This work is the first part of a [larger supply-chain hardening goal](https://goals.rust-lang.org/2026/crates-io-supply-chain-hardening.html) that will eventually enable publish-time scanning of crates. Feedback from members of the upstream Cargo and crates.io teams has and is being addressed and we expect this RFC to be proposed for acceptance within the next month.

# Rust/C++ Interop

Teor’s experiments with [representing C++ overloads in Rust](https://github.com/rustfoundation/overloading-macros/tree/main) continue, over the past few weeks, [Outreachy applicants](https://www.outreachy.org) have been turning C++ standard library overloads into experimental Rust overload code. Eventually, we hope to reduce the amount of manually written Rust glue code via automated binding generation for overloaded functions, reducing the risk of manual errors in unsafe code.

The RFC to formalise Rust support for external linkers [continues to make progress](https://github.com/rust-lang/rfcs/pull/3993#issuecomment-6353826121). While not directly security-related, consistent expectations around stability guarantees reduce the risk of bugs and miscompiles. Any small risks in this area are multiplied by the widespread usage of these unstable features by multiple projects with billions of end users.

At RustConf, the Rust Commercial Network had a meeting about C++ to Rust translation, focusing on coordination and strategies to avoid duplicate automated translations. In general, switching to Rust can improve security due to additional memory safety checks. But this kind of coordination is important to ensure translations are high quality, actually improve security in practice, and any remaining security issues can be resolved in a single place. [Discussions are ongoing on the Rust Zulip](https://rust-lang.zulipchat.com/#narrow/channel/594428-commercial-network/topic/C.2FC.2B.2B.20to.20Rust.20Translation/with/622865688).

# Infrastructure and crates.io

Marco and Ubi have been reviewing the work of the Project’s infrastructure team to roll-out Trusted Publishing to 13 more repositories in the rust-lang and rust-analyzer GitHub organisations, which has enabled the removal of all of the long-lived crates.io publish tokens from the rust-lang-owner GitHub account (a bot account used for many automations in the Rust Project).

Similarly, Marco and Ubi have been reviewing changes which extend crabwatch, our GitHub Actions auditing tool, to eight more repositories and enabled more zizmor lints.

Marco wrote up [the Q3 achievements and Q4 plan for the infrastructure team](https://blog.rust-lang.org/inside-rust/2026/10/12/infrastructure-team-q3-recap-and-q4-plan/) and completed work that prevented users from bypassing crates.io’s CDNs.

Tobias continued his work to migrate crates.io metrics to OpenTelemetry, enabling performance tracing, further increasing operational visibility into the platform.
