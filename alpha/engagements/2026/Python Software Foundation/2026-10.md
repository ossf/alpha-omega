# 2026-10

## PyPI Safety & Security Engineer (Mike Fiedler)

### Malware & Abuse Response

274 malware reports arrived in October, up from 151 in September,
covering 246 packages.
One independent researcher filed 68% of them.
Mike filed 43 more by tracing campaigns from external reports back to older packages,
and removed all of them.

129 reports were confirmed malicious, two were false alarms, and 143 are still under review.
Trusted observers had no false positives.
The median package was reported 1.8 hours after upload and acted on within 1.0 hour,
both faster than September.
Auto-quarantine contained 146 packages (59%) as soon as reports arrived.

The review backlog grew.
137 packages await a final decision, most of them reported during Mike's PTO,
and two thirds are already quarantined.
Full removal took a median of 31 hours before the PTO and 50 hours across the month.
Six older reports closed, including the 28-package report from July,
and 189 report conversations remain open, the oldest from June.

Mike also made quarantine
[tag the matching Help Scout conversation](https://github.com/pypi/warehouse/pull/20847)
and [upgraded Inspector](https://github.com/pypi/inspector/pull/335) for triage.

## Seth Larson (Security Developer-in-Residence)

Onboarded Brett Smith, new Security Developer at the PSF.
Co-authored a [blog post announcing his joining](https://pyfound.blogspot.com/2026/10/announcing-new-security-developer-2026.html).
Getting Brett up to speed with Python Security Response Team and CVE
Numbering Authority processes and tools at the PSF.

A week of October was spent responding across the Python
ecosystem to the eMudhra intermediate certificate compromise,
coordinating fixes with PSF services like Python.org and PyPI,
Python core developers, Python packaging
maintainers, and other affected projects.
Authored a blog post (publishing early November) about
the PSF and Python ecosystems' response to the eMudhra
intermediate certificate compromise.

Published 9 vulnerabilities for CPython, truststore, and related projects:

* [CVE-2026-116566] socket.getaddrinfo() accepts embedded null bytes in host and port
* [CVE-2026-103995] Lenient parsing of integers for response body and chunk framing
* [CVE-2026-115557] Distrust compromised intermediate certificates in ssl module
* [CVE-2026-114583] tarfile.tar_filter path traversal bypass allows writing outside the extraction directory
* [GHSA-6q48-6c7w-9gw2] CRITICAL security update for certifi, removal of emSign root certificate
* [CVE-2026-119170] FIPS issue on CPython 3.14.10
* [GHSA-pmqj-r2x2-vx88] Concurrent handshakes with a shared `SSLContext` may disable certificate verification of subsequent handshakes on Windows and macOS
* [GHSA-8v28-6h89-pmvr] SSLContext.wrap_socket() missing validation of server_hostname parameter for macOS and Windows
* [CVE-2026-111497] Upgraded libbrotli to v1.2.1, which remediates CVE-2026-111497, an out-of-bounds write that permits remote code execution

Work is ongoing to publish a Security Roadmap for the PSF in 2027 which
aims to address compromise resilience, post-quantum cryptography, PyPI malware
remediation sustainability (reducing manual effort), and vulnerability capacity.
